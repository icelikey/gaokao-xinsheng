# M6 Verification Log

## Scope

Local sharing and operations loop: report share-card creation, public share page privacy boundary, and admin review queue preview.

## Current Status

Partially verified locally on 2026-06-29.

This is not a production sharing pipeline yet. Hosted Supabase Storage has not been exercised against a real dev project. The milestone proves the service contract, public-field boundary, report link path, wrong-question review path, local 1080x1440 PNG poster generation and review queue UI shape.

Note: the earlier browser smoke used no post-AI correction, so public independent and collaborative scores were equal. The current store-backend contract now separately proves a pre-AI wrong answer and post-AI corrected answer produce a 5-point dual-score delta.

## Evidence

- Report page can create a share card:
  - `POST /api/v1/reports/:reportId/share-cards`
  - requires `Idempotency-Key`
- Public share API exists:
  - `GET /api/v1/share/:token`
  - returns only `publicFields`
  - does not expose answer versions, per-question answers or private report internals
- Share poster generation exists:
  - memory mode returns a `data:image/png;base64,...` poster URL for local preview
  - Supabase mode uploads the PNG to the `share-cards` Storage bucket and writes `share_cards.object_url`
- Share visibility controls exist:
  - Web report page and miniprogram report page can toggle independent score, AI collaborative score, paper title and region
  - hidden score fields become `null` in `publicFields`
  - public Web and miniprogram share pages conditionally render only non-null public fields
- Admin review queue API exists:
  - `GET /api/v1/admin/review-queue`
- Admin review workflow API exists:
  - `PATCH /api/v1/admin/review-queue/:reportId`
  - supports `ASSIGN`, `RESOLVE` and `REJECT`
  - memory mode writes an audit record for every state transition
  - Supabase mode writes `review_tasks` and `audit_logs`
- Admin manual score adjustment API exists:
  - `POST /api/v1/admin/review-queue/:reportId/score-adjustments`
  - validates `questionId`, `score`, `actor` and `reason`
  - memory mode updates the report question and writes before/after score audit data
  - Supabase mode updates `grading_results`, recalculates `exam_reports.collaborative_score` and writes `audit_logs`
- Browser pages exist:
  - `/reports/:reportId/mistakes`
  - `/share/:token`
  - `/admin/review-queue`
- Web report contract check exists:
  - `pnpm test:report-contract`
  - checks the report-to-mistakes link, the missed-score/review-required filter, poster bitmap contract and the public share private-field boundary
- Share edge-case check exists:
  - `pnpm test:share-edge-cases`
  - generates deterministic 1080x1440 PNG evidence for 0 score, full score, long paper/region public fields and hidden score/paper/region fields
  - checks mobile share viewport CSS contracts for bounded card width, poster max height and one-column score layout
- Review workflow contract check exists:
  - `pnpm test:review-workflow`
  - checks the action route, shared schema, admin buttons, manual score-adjustment route, `review_tasks` migration, `audit_logs` writes and terminal queue filtering
